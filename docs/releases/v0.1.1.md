# v0.1.1

`v0.1.1` は、`v0.1.0` の後に直した「フォルダへ移動」シートまわりの不具合と、配布の整備を含む Stable である。
Preview `preview-v0.1.1-1`（`52a4246`）を、配布 ZIP で実機に確かめた。
`52a4246` より後に入った変更はドキュメントだけで、アプリの動作は Preview と同じである。
このファイルを追加しただけでは公開にならない。
Stable の tag、GitHub Release、添付の `SHA256SUMS` がそろったときに、正式版として扱う。
`v0.1.2` 以降に入る変更は、[未リリースの変更](./unreleased.md) に記録する。
最初の Stable `v0.1.0` の内容は、[v0.1.0 のリリースノート](./v0.1.0.md) にある。

## 変更

- 「フォルダへ移動」シートを先に開いた状態から注入したとき、シートが残って移動していないのに成功として扱われる問題を直した（#95）。Return を送った後、シートが閉じたことを確かめてから成功とする。閉じなければ（閉じたことを確かめられない場合も）AX で値を入れ直して確定し直し、それでも閉じなければパレットに「移動できませんでした（「フォルダへ移動」を確定できません）」と出す。Cmd+Enter の「開く」も、シートが閉じたのを確かめてから押す。
- 先に開いた「フォルダへ移動」シートでは、確定の Return をシステム経由で送るようにした（#95）。macOS 26 の VS Code のパネルでは、アプリへ直接送った Return がシートに届かなかったため。⌘⇧G は送らないため、Raycast などの ⌘⇧G のホットキーには影響しない。
- `/tmp` の下のフォルダへ移動するとき、「フォルダへ移動」シートの候補が実体の `/private/tmp` を示しても、同じ場所として扱うようにした（#95）。`/var`・`/etc` も同じ。確定前に候補を待つ時間（最大 250ms）が減る。

## 配布と開発環境の変更

- 英語 README にも Homebrew tap からのインストールと初回起動の手順を追加した。
- Homebrew tap から `v0.1.0` をインストールできることを確認し、README にインストール手順を追加した（#117）。
- Stable の公開後に、GitHub App で Homebrew tap（`TamaT-LLC/homebrew-tap`）へ cask の更新 Pull Request を自動で出し、auto-merge を要求するようにした（#116）。
- cask の最小 macOS を `depends_on macos: ">= :sonoma"` から `depends_on macos: :sonoma` に改めた（#116）。Homebrew 6.0.0 から記号だけで「Sonoma 以降」を表し、`">= :sonoma"` は非推奨で `brew style` が失敗するためである。Homebrew 5.x 以前はこの書き方を「Sonoma のみ」と解釈する。
- Swift 6.3 の Command Line Tools だけの環境で、`./scripts/test.sh` がテストを 1 件も実行できずに異常終了する問題を直した（#113・#114）。Swift Testing が依存する `lib_TestingInterop.dylib` の置き場所を rpath に加える。この dylib が無い CLT（Swift 6.2 以前）と Xcode では、渡す引数は変わらない。アプリの動作には影響しない。

## 既知の制約

- アクセシビリティ API とキー入力に関わる挙動は CI で確かめられないため、[手動シナリオテスト](../50_test/test-openpath-manual-scenarios.md) で確認する。
- `roots` に保護フォルダを含むときの macOS の確認の挙動は、実機で確かめる途中である（手動シナリオの ONB-20）。
- 自動更新の機能は無い。新しい version は GitHub Releases または Homebrew から入れ直す。
- テンキーの Enter は、Return の代わりとしては扱わない。
- 通常の注入（ファイル一覧や検索欄にフォーカスがある状態）で、⌘⇧G を物理キーボードと同じ経路で送り直すことがある。この経路の ⌘⇧G は Raycast などのグローバルホットキーに横取りされうる。Raycast で ⌘⇧G を設定した環境では、Raycast が開き、openpath は「⌘⇧G が開きません」と表示する。`v0.1.0` からの制約で、`v0.1.1` でも変わらない。先に開いたシートからの注入は、⌘⇧G を送らないため影響を受けない。
- macOS 27 の VS Code では、通常の注入で貼り付け後の確認が一致せず（fieldMismatch）、入力欄を直接書き換える副方式に移ることがある。移動は成功するが、1.7〜1.9 秒かかった。全体の上限は 2.5 秒である。

### 実機で確かめていない項目

次の項目は、`v0.1.1` の時点では実機での確認が済んでいない。
`v0.1.2` 以降で確かめ、結果を [未リリースの変更](./unreleased.md) に記録する。
自動テストで守られている項目は、その旨を添える。

- #90: Return のリピートが背後のパネルに届いて確定される問題の、物理キーの長押しでの確認（PAL-08）。CI の Enter 長押しとリピート消費のテストは成功している。
- #91: 初期構築が遅いときに、候補なしのメッセージが一瞬見えないことの目視（FLOW-01）。
- #92: 候補の構築中に履歴をクリアしても、履歴だけの候補が残らないこと（MENU-05）。CI の関連テストは成功している。
- #95: 移動先シートが閉じないときの、再確定とエラー表示の実機での確認（INJ-02）。CI では、副方式での再確定、閉じたことを確かめられないときのエラー、「開く」を押さないことが成功している。
- キー配列の自動判定（#68・#107）。Dvorak や Colemak など QWERTY 以外の配列での確認（INJ-05）は済んでいない。
- #94: 配布版での確認（INJ-01）。macOS 26 のローカルビルドでは成功している。
- VS Code のサイドバーからの通常の注入（INJ-07）。
