# v0.1.0（最初の Stable）

`v0.1.0` は openpath の最初の Stable である。
対象のコミットは `726dc52` で、Preview `preview-v0.1.0-2` と同じコミットに tag を付けて公開する。
Preview `preview-v0.1.0-1` と `preview-v0.1.0-2` を実機で確かめ、結果を [Issue #29](https://github.com/TamaT-LLC/openpath/issues/29) に記録した。
このファイルを追加しただけでは公開にならない。
Stable の tag、GitHub Release、添付の `SHA256SUMS` がそろったときに、正式版として扱う。
`v0.1.1` 以降に入る変更は、[未リリースの変更](./unreleased.md) に記録する。

## 最初のリリースに含める機能

- ファイル選択パネル（NSOpenPanel）の出現を検知し、ファジー検索のパレットを重ねる。保存ダイアログと `disabled_apps` のアプリでは出さない。
- 候補は、確定したパスの履歴（frecency）、ghq のリポジトリ、`roots` の配下から作る。候補は 5 分ごとと、メニューの「候補を再構築」で作り直す。
- 選んだパスを「フォルダへ移動」（⌘⇧G）とクリップボード経由の貼り付けでパネルに入力する。入力欄をアクセシビリティ API で直接書き換える副方式を持つ。入力後はクリップボードを元に戻すが、機密の印（`org.nspasteboard.ConcealedType`）が付いた内容は退避せず、入力の成否に関わらず空にする。入力中にコピーされた内容は残す。
- パスの入力は全体で 2.5 秒まで待ち、終わらなければ打ち切ってパレットにエラーを出す。macOS 26 の VS Code など移動先シートが開くのが遅いアプリで、1 回目の入力が途中で打ち切られないよう、Preview `preview-v0.1.0-1` の 1.5 秒から延ばした（#29）。
- Enter は移動までで止め、Cmd+Enter または `auto_confirm = true` のときは「開く」まで押す。
- メニューバーから、有効と無効の切り替え、候補の再構築、設定ファイルを開く操作、履歴のクリア、ログイン時の起動を操作できる。
- 設定ファイル `~/.config/openpath/config.toml` を保存すると自動で読み込み直す。初回は、ghq の root、ghq が無ければホーム（`~`）を `roots` に書いて生成する。
- 初回起動で、アクセシビリティ権限の用途の説明、許可の案内、「試してみる」を順に表示する。
- ログを `~/Library/Logs/openpath/` に出力する。パスは debug レベルでだけ記録する。

## 動作環境と配布

- macOS 14 以降。ZIP は Apple Silicon と Intel の両方を含む Universal 形式。
- Stable は Developer ID で署名し、Apple の公証を受ける。Homebrew cask（`openpath.rb`）を添付する。
- Preview は ad-hoc 署名で公証しない。評価用で、サポート対象外。
- 画面の表示は日本語だけ。

## 公開前に実機で確かめたこと

- Preview `preview-v0.1.0-1`（`3ab25a1`）の実機確認で、VS Code の通常の移動で移動先シートを開けない不具合が見つかった。
- この不具合には、移動先シートを 3 段で開く変更（#110）と、全体のタイムアウトを 2.5 秒に延ばす変更（#111）で対処した。
- Preview `preview-v0.1.0-2`（`726dc52`）では、TextEdit・VS Code・Cursor・Claude・Safari の 5 つのアプリで、移動を計 8 回行い、すべて成功した。
- 注入時間は 0.24〜1.69 秒だった。以前の全体タイムアウト（1.5 秒）を超える処理も、途中で打ち切られずに完了した。
- 日本語や空白を含むパス、Cmd+Enter（自動確定）、Esc、保存画面でパレットを出さないことも、期待どおりだった。
- 本体の不具合は、この確認では再現しなかった。

## 既知の制約

- アクセシビリティ API とキー入力に関わる挙動は CI で確かめられないため、[手動シナリオテスト](../50_test/test-openpath-manual-scenarios.md) で確認する。
- `roots` に保護フォルダを含むときの macOS の確認の挙動は、実機で確かめる途中である（手動シナリオの ONB-20）。
- 自動更新の機能は無い。新しい version は GitHub Releases または Homebrew から入れ直す。
- テンキーの Enter は、Return の代わりとしては扱わない。
- macOS 26 の VS Code など、ファイル選択パネルを別のプロセスが描くアプリでは、「フォルダへ移動」（⌘⇧G）を物理キーボードと同じ経路で送り直すことがある。この経路の ⌘⇧G は Raycast などのグローバルホットキーに横取りされうるため、ファイル一覧にフォーカスが無い状態では、入力欄を直接書き換える副方式での移動になるか、移動できないことがある。

### 実機で確かめていない項目

次の項目は、`v0.1.0` の時点では実機での確認が済んでいない。
`v0.1.1` 以降で確かめ、結果を [未リリースの変更](./unreleased.md) に記録する。

- キー配列の自動判定（#68・#107）。現在の入力ソースのキー配列から、⌘⇧G などのキーコードを求める。Dvorak や Colemak など QWERTY 以外の配列での確認（手動シナリオの INJ-05）は済んでいない。
- Raycast などのグローバルホットキーとの競合（手動シナリオの INJ-06）。⌘⇧G を注入先のプロセスへ直接送る対策（#107）は入れたが、Raycast と競合する条件のすべては確かめていない。
- 次の Issue で直した挙動の、個別の条件での確認。
  - #90: Return のリピートが背後のパネルに届いて確定される問題（PAL-08）。
  - #91: パレットを初めて出したときに、候補なしのメッセージが一瞬見える問題（FLOW-01）。
  - #92: 候補の構築中に履歴をクリアしても、履歴だけの候補が残る問題（MENU-05）。
  - #94: 注入中に別のアプリへ切り替えたとき、エラー表示と再試行用のパレットが残らない問題（INJ-01）。
  - #95: 「フォルダへ移動」のシートを先に開いた状態からの注入が失敗する問題（INJ-02）。
